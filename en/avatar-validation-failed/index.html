What you see on screen:

Build Failed Your avatar failed to build or upload because of the following reason Avatar validation failed (Console) Encountered the following validation issues during build: (the real reasons are listed below this line, one per red line)

What it means

This is a summary message: the VRChat SDK checked your avatar during the build and found one or more red items (errors). The message itself doesn't say which. The reasons are logged in the Unity Console as red lines right below "Encountered the following validation issues during build:" (checked on SDK 3.10.6). In the SDK panel, the message appears under "Build Failed", and the "Check Console for more details" button opens the Console. Since SDK 3.3.0 this check runs on the avatar after upload-time tools such as Modular Avatar and VRCFury have finished processing it, so a build can fail even when nothing is red in the panel beforehand.

Common causes

  • Only one of Expressions Menu and Parameters is set ("VRCExpressionsMenu / VRCExpressionParameters object reference is missing.")
  • Too many synced parameters ("VRCExpressionParameters has too many parameters defined.") - parameters that tools add during the build are counted here too
  • The menu uses a name that isn't in the parameter list ("VRCExpressionsMenu uses a parameter that is not defined.")
  • Audio, particle or texture settings (an audio clip without Load In Background, particles that destroy themselves when they stop, textures without Streaming Mip Maps, etc.)
  • PhysBone chains that are too deep ("maximum dependency depth") - this can happen only after tools have processed the avatar
  • On Android/Quest: a shader outside VRChat/Mobile ("Avatar uses unsupported shader")
  • Missing Humanoid bone mappings ("Humanoid avatar must have head, hands and feet bones mapped." and similar)

How to tell which cause it is

  • A red item is already listed under "2. Review Any Alerts" before you build
    → That item is the reason. Select (on the right) selects the object; if there is an Auto Fix button, it fixes it
  • Review Any Alerts shows only yellow items (or nothing), but the build still fails
    → The avatar has a red item after upload-time tools processed it. Read the lines below "Encountered the following validation issues during build:" in the Console
  • The red Console line mentions too many parameters or dependency depth
    → Parameters or PhysBones added by a tool push you over a limit. If a copy without that tool builds fine, that tool is the cause
  • The failure message is something else, like "Avatar download size is too large for the target platform"
    → That isn't this error. Look up the cause of that message instead (for example, the size limits)

How to fix it

  1. Open VRChat SDK > Show Control Panel > Builder and read every red item under "2. Review Any Alerts" (yellow items are warnings only and don't stop the build)
  2. Open the Console (Window > General > Console), press Clear, build again, and read the red lines right below "Encountered the following validation issues during build:"
  3. If a red item in Review Any Alerts has a Select button, press it to select the object. If it has Auto Fix, copy your project first, then press it
  4. For items without Auto Fix, search for the Console message on this site and fix it (for example: object reference is missing > the Expressions fields; too many parameters > sync fewer parameters)
  5. If an item shows up only during the build and not in Review Any Alerts, something an upload-time tool added is the cause. Duplicate the avatar in the scene, remove that tool's components from the copy one at a time, and build the copy to see which one stops it
  6. If the Console shows no reason at all, update the VRChat SDK in VCC or ALCOM and build again
  7. When no red lines are left, press Build again

Common mistakes

  • Searching for "Avatar validation failed" itself rarely finds the answer. Search for the red line logged before it in the Console.
  • You don't have to clear every yellow item (Warning). Only red items (Errors) stop the build.
  • "Loaded data for an avatar we do not own, clearing blueprint ID" nearby is a yellow warning, not the reason the build stopped.
  • Going over the size limit doesn't produce this message. That shows a different one, "Avatar download size is too large for the target platform", at the upload stage after the build.
  • It is not the same as "Security Checks Failed". That appears when VRChat's servers block an avatar after it has been uploaded.

FAQ

Why does it fail when nothing is red in the SDK panel?

Since SDK 3.3.0, the check runs on the avatar after upload-time tools (Modular Avatar, VRCFury, etc.) have finished processing it. Problems like going over the parameter limit because of parameters a tool added, or PhysBone chains becoming too deep, are only found during the build. Read the messages below "Encountered the following validation issues during build:" in the Console.

Will turning off a VPN or logging in again fix it?

No. This error comes from a check inside Unity, so network changes and logging in again won't clear it. You need to fix the cause shown in the red Console lines.

Is it safe to press Auto Fix?

Auto Fix only appears on items the SDK knows how to fix (adding a Pipeline Manager, converting Dynamic Bones to PhysBones, etc.). It changes your avatar, so copy your project folder first if you want to be able to go back.

It only fails for Quest (Android)

On Android, only shaders from VRChat/Mobile are allowed. If the Console says "Avatar uses unsupported shader", that's the reason. Switch the Quest materials to VRChat/Mobile shaders and build again.

Before you change anything, make a full copy of your project folder so you can go back.
