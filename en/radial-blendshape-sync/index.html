What you see on screen:

(No error message - a blendshape on a radial slider doesn't reach the value you expect, or moves in steps for others)

What it means

A radial menu drives a float parameter from 0 to 1 (floats range from -1 to 1), and an animation maps that to the blendshape's 0-100. Floats sent to other players have 255 possible values (1/127 precision), so fine movement looks slightly steppy. Each synced float costs 8 bits out of the 256-bit total.

Common causes

  • Trying to set the parameter straight to 100 (a float only goes up to 1)
  • The animation isn't built from a 0 clip and a 100 clip
  • Too many synced floats pushed the total over 256 bits

How to fix it

  1. Make one clip with the blendshape at 0 and one at 100, and blend them with a 1D blend tree (or Motion Time) driven by the float from 0 to 1
  2. Small steps for other players come from how floats sync - usually fine to leave as is
  3. If you have too many sliders, turn off Synced for the ones others don't need to see
